Symbol

Refinery 의 핵심 브랜드 마크입니다. 두 개의 꺾쇠 모양이 맞물려 데이터를 정제(refine)하는 흐름을 상징합니다. 심볼은 단일 형태만 사용하며 색상은 컨텍스트의 텍스트 색을 currentColor 로 상속받습니다 — 별도 색상 토큰을 정의하지 않습니다. Rail 로고 · 온보딩 일러스트 · 빈 상태 강조 등은 어디서 호출하든 동일한 SVG 를 그대로 재사용합니다. 단, 파비콘만은 예외 — 브라우저 탭 컨텍스트는 currentColor 상속이 불가하므로, 자체 배경·고정 색을 가진 단독 정적 파일(fav_refienry-symbol.svg)을 사용합니다 (아래 Favicon 섹션 참조).
The Mark

심볼은 32×32 viewBox 위에 정의된 단일 SVG 입니다. 두 개의 path 가 좌상단·우하단에서 마주보며 미러 구조를 이룹니다. 어떤 컨테이너 안에서도 비례를 유지하도록 viewBox + currentColor 만으로 렌더하며, 별도의 PNG · JPG 버전은 만들지 않습니다.

Color Variants

심볼은 단일 색상으로만 사용합니다 — 어떤 그래디언트·이중 톤도 적용하지 않습니다. 색상은 컨테이너의 텍스트 색을 currentColor 로 상속하므로 별도의 fill 지정이 필요 없습니다. 라이트 배경 위에서는 ink-900(#16202C), 다크 배경 위에서는 ink-900 dark(#EDEEF0)로 자동 반전됩니다.

Clear Space

심볼 주위에는 항상 최소한의 여백을 확보합니다. 클리어 스페이스는 심볼 너비의 1/4(32×32 viewBox 기준 8 단위) 이며, 이 영역 안에는 다른 텍스트·그래픽·테두리를 배치하지 않습니다. 아래는 30px 그리드 위에 심볼을 올린 후 클리어 스페이스(파란 점선)를 표시한 예입니다.

Favicon · 단일 정적 심볼

파비콘은 단일 정적 SVG 파일(fav_refienry-symbol.svg) 하나만 사용합니다. 이 파일은 불투명 다크 배경(#131519) + 밝은 심볼(#EDEEF0)을 자체 포함하므로, 브라우저·OS 의 라이트/다크 모드나 Chrome Incognito 와 무관하게 항상 동일한 모습으로 표시되고 어떤 탭 배경 위에서도 충분한 대비를 유지합니다. media 분기·SVG 내부 미디어쿼리·JS 강제 주입 같은 적응 로직이 전혀 필요 없어, Chromium 의 파비콘 캐싱이나 prefers-color-scheme 미반영(Incognito) 같은 엣지케이스가 원천적으로 발생하지 않습니다. rel → type → href 순의 단일 <link> 한 줄로 끝납니다.

Rules · Do & Don't

Symbol 시스템의 핵심 규칙입니다. 새 페이지·기능에 Symbol 을 배치할 때 예외 없이 적용됩니다.

DO
심볼은 항상 단일 SVG 원본을 그대로 사용합니다. 어떤 호출처에서도 같은 viewBox + 같은 path 를 호출합니다.
색상은 currentColor 로 상위 텍스트 색을 상속받습니다. 라이트 배경 위에서는 ink-900(#16202C), 다크 배경 위에서는 ink-900 dark(#EDEEF0).
사이즈는 정해진 토큰(XS 16 · SM 28 · MD 48 · LG 64 · XL 120+) 안에서만 사용합니다.
심볼 주위에 항상 심볼 너비의 1/4 이상의 클리어 스페이스를 확보합니다.
파비콘은 단일 정적 SVG(fav_refienry-symbol.svg) 하나만 사용합니다. 자체 다크 배경(#131519)+밝은 심볼을 포함해 라이트/다크/Incognito 무관하게 동일하며, media 분기·JS 강제 주입 없이 단일 <link> 한 줄로 끝납니다.
"Refinery" 워드마크와 함께 노출할 때는 심볼 다음에 워드마크를 배치합니다 (좌→우 읽기 순서).
DON'T
심볼에 그래디언트·이중 톤·테두리·그림자를 적용하지 않습니다. 단일 색 fill 만 사용합니다.
심볼의 비례·회전·미러링을 변경하지 않습니다 — viewBox 와 path 는 절대 수정하지 않습니다.
심볼을 brand(Refined Blue)나 semantic(good/warn/bad) 컬러로 칠하지 않습니다. ink 톤만 사용.
심볼 위에 다른 그래픽·텍스트·아이콘을 겹쳐 두지 않습니다.
PNG·JPG·ICO 등 별도 래스터 자산을 만들거나 사용하지 않습니다 — 항상 SVG.
16px 미만 사이즈에서는 사용하지 않습니다 — 디테일이 손상됩니다.

Layout

Refinery 의 모든 페이지가 공유하는 App Shell 입니다. 페이지를 새로 추가할 때 가장 먼저 이해해야 하는 가장 큰 단위의 구조이며, 화면은 항상 Global Nav(.rail) · Sub Nav(.side) · Header(.topbar) · Content Canvas(.page) 4개 영역으로 구성됩니다. 각 영역의 폭/높이·padding·tone 토큰은 라이트·다크 모드 모두에서 동일한 의미 인덱스로 유지되며, 모든 신규 페이지는 이 4개 영역 위에서만 동작해야 합니다.
App Shell · Anatomy

App Shell 은 3-column CSS Grid 로 구성됩니다 — grid-template-columns: 200px 240px 1fr. 좌측부터 Rail(Global Nav) · Side(Sub Nav) · Main, 그리고 Main 내부는 다시 Topbar(Header)와 Page(Content Canvas)의 세로 분할로 이뤄집니다. Side 는 collapse 가능, Rail 은 1200px 이하에서 축소, 720px 이하에서 icon-only 로 전환됩니다.

Scroll Fade · 스크롤 페이드 separator

Global Nav(.rail)·Sub Nav(.side)의 스크롤 영역과 하단 고정 영역(계정 도크·접기 바) 사이 경계를 1px 보더 대신 그라데이션 페이드로 처리하는 App Shell affordance 입니다. 스크롤 콘텐츠가 하단 고정 영역 뒤로 자연스럽게 사라져 "아래에 더 있음"을 암시합니다. 바닥까지 스크롤했거나 overflow 가 없으면(.at-bottom) 페이드를 숨겨 불필요한 그림자를 남기지 않습니다.

Rules · Do & Don't

Layout 시스템의 핵심 규칙입니다. 새 페이지·기능을 추가할 때 예외 없이 적용됩니다.

DO
모든 페이지는 Rail · Side · Topbar · Canvas · Page Header 의 5개 영역 위에서만 동작합니다.
App Shell 너비는 200 · 240 · 1fr 토큰을 그대로 따릅니다 (1440↓ 180 · 220 · 1fr).
페이지 내 유일한 스크롤 영역은 .page 입니다. Rail/Side/Topbar 는 항상 고정.
페이지별 액션(+ Add · 새로고침 · 내보내기)은 Page Header 우측에 배치합니다. Topbar 는 전역 액션 전용.
Page Header 의 h1 은 항상 22px / 700 / Pretendard 입니다.
다크 모드에서 Rail 은 페이지보다 어두운 톤(#131519), Topbar 는 흰색으로 반전해 상하 위계를 만듭니다.
Page 배경은 항상 --ink-50, 그 위에 흰/#191D22 카드(.rfn-widget)가 떠 있는 2-depth 구조를 유지합니다.
밀도 변경은 .page 의 zoom 으로만 적용 — Rail/Side/Topbar 는 영향을 받지 않습니다.
DON'T
App Shell 의 4개 영역 외에 임의의 fixed/floating 패널을 추가하지 않습니다 (Modal/Popover/Toast 제외).
Rail/Side 의 너비를 정의된 토큰 외 임의 값(예: 220px, 260px)으로 변경하지 않습니다.
페이지 내부에 별도의 스크롤 컨테이너를 두지 않습니다 — .page 한 곳에서만 스크롤.
페이지별 액션을 Topbar 의 actions 영역에 추가하지 않습니다 (전역 액션 영역 오염).
Page Header 의 h1 을 다른 폰트(Roboto · Mono)나 다른 사이즈로 사용하지 않습니다.
Page 배경 위에 직접 차트/리스트를 노출하지 않습니다 — 항상 .rfn-widget 등의 카드 위에 올립니다.
밀도 토큰 외 임의의 zoom 값(0.85, 1.10 등)을 적용하지 않습니다.
Side 가 collapse 된 상태에서 페이지 내용을 강제로 한 컬럼으로 재구성하지 않습니다 — 그리드 시스템에 맡깁니다.

테마는 단일 키 refinery-theme 로 3파일 공유.

Color 시스템의 핵심 규칙입니다. 새 페이지·기능에 색을 적용할 때 예외 없이 적용됩니다.

DO

DON'T
토큰에 없는 임의의 hex 값을 새로 만들지 않습니다 — 필요한 경우 디자인시스템 확장을 먼저 합의합니다.

Rules · Do & Don't

Typography 시스템의 핵심 규칙입니다. 새 페이지·기능에 텍스트를 적용할 때 예외 없이 적용됩니다.

DO
영문은 --font-en (Roboto), 국문은 --font-kr (Pretendard) 을 사용합니다. 혼용 텍스트는 한 노드 안에서 영문 폰트를 우선 선언하여 라틴 글리프가 Roboto 로 렌더되도록 합니다.
화면에 표기되는 모든 텍스트는 정의된 타입 스케일 토큰 안에서만 사용합니다 — Display · Title · Body · Caption · Meta 의 위계를 지킵니다.
수치는 .num 클래스(font-variant-numeric: tabular-nums) 로 자릿수를 정렬합니다. 표·KPI·델타에서 자릿수가 흔들리지 않도록 합니다.
Mono 폰트(--font-mono) 는 코드·토큰명·hex·kbd 등 식별자/리터럴 표기에만 사용합니다.
본문은 ink-800, 보조 텍스트는 ink-600, 비활성/플레이스홀더는 ink-400 의 위계를 지킵니다.
행간은 본문 1.5, 캡션 1.45, 제목 1.25 ~ 1.35 를 기본 비율로 사용합니다. 자간(letter-spacing) 은 토큰에 정의된 값만 사용합니다.
DON'T
토큰에 없는 임의의 폰트 사이즈·웨이트를 새로 사용하지 않습니다 — 필요한 경우 디자인시스템 확장을 먼저 합의합니다.
Mono 폰트를 일반 본문·라벨·버튼 텍스트에 사용하지 않습니다 — 가독성과 위계가 무너집니다.
입력값(<input>·<textarea>) 에 Mono 폰트를 강제하지 않습니다. 단축키 표기용 <kbd> 만 예외입니다.
Pretendard·Roboto·JetBrains Mono 이외의 외부 웹폰트를 임의로 추가하지 않습니다.
본문 텍스트를 브랜드 컬러로 칠하거나, 의미 컬러(good/warn/bad) 로 일반 글자를 강조하지 않습니다.
제목·라벨에 text-transform: uppercase 를 임의로 적용하지 않습니다 — Eyebrow / Section label 등 토큰에서 정의된 영역에서만 사용합니다.

Rules · Do & Don't

Icon 시스템의 핵심 규칙입니다. 새 페이지·기능에 아이콘을 추가할 때 예외 없이 적용됩니다.

DO
모든 아이콘은 Phosphor Regular(.ph) 한 가지 가중치로 통일합니다.
크기는 7단 토큰(XS 10 · SM 12 · MD 14 · LG 16 · XL 18 · 2XL 24 · 3XL 32) 안에서만 사용합니다.
색상은 currentColor 를 통해 상위 텍스트 색을 상속받습니다. 별도 색을 지정해야 하면 ink/brand/semantic 토큰만 사용합니다.
아이콘 단독(icon-only) 사용 시 반드시 title 또는 aria-label 을 제공합니다.
같은 의미에는 같은 아이콘을 사용합니다 — 예: 검색은 항상 magnifying-glass, 더보기는 항상 dots-three.
Fill 가중치는 "비어 있음 ↔ 채워짐" 의미가 필요한 경우(즐겨찾기 별 등)에만 예외적으로 사용합니다.
새 아이콘이 필요할 때는 phosphoricons.com 에서 Regular 가중치 아이콘을 골라 추가합니다.
DON'T
Light · Thin · Bold · Duotone 등 다른 Phosphor 가중치를 혼용하지 않습니다.
Phosphor 외 다른 아이콘 라이브러리(Material · Heroicons · FontAwesome 등)를 섞어 사용하지 않습니다.
11px · 13px · 15px · 17px · 20px · 22px 등 토큰 외 임의 사이즈를 사용하지 않습니다.
아이콘 단독 버튼에 title/aria-label 없이 노출하지 않습니다 (접근성 위반).
같은 의미에 서로 다른 아이콘(예: 검색에 funnel)을 임의로 사용하지 않습니다.
장식 목적으로 Fill 가중치를 사용하지 않습니다 — Regular 보다 시각 무게가 커서 위계가 깨집니다.
아이콘에 그림자·테두리·그라데이션 효과를 별도로 적용하지 않습니다. (배경 컨테이너는 가능)

Grid

Refinery 의 모든 페이지에 일괄 적용되는 16-column 가변 그리드 시스템입니다. 컨테이너는 fluid (max-width 제한 없음)이며, 페이지 padding 과 그리드 gutter, breakpoint 별 컬럼 재구성 규칙은 모든 페이지에서 동일한 토큰으로 유지됩니다.
Anatomy

그리드의 구성 요소는 Margin (페이지 좌우 padding), Column (균등 분할 트랙), Gutter (컬럼 사이 gap) 3가지입니다. 기본 데스크탑 기준 16개의 컬럼이 1fr로 균등 분할되며, 컬럼 사이엔 14px gutter가 들어갑니다. 페이지 좌우 24px의 margin이 컨텐츠를 감싸 카드/위젯이 페이지 가장자리에 붙지 않도록 합니다.

Breakpoints · Responsive Behavior

화면 폭에 따라 컬럼 수와 페이지 padding이 자동 재구성됩니다. 컬럼 수는 16 → 8 → (collapse) 16 으로 변하며, 좁은 화면에서는 모든 영역이 span 16(전체 폭)으로 단일 컬럼화됩니다. 이 breakpoint 값들은 모든 페이지에 동일하게 적용되며, 페이지별로 추가 breakpoint를 정의하지 않습니다.

Rules · Do & Don't

Grid 시스템의 핵심 규칙입니다. 새 페이지·기능을 추가할 때 예외 없이 적용됩니다.

새 레이아웃은 우선 정의된 패턴(8+8, 4×4, 11+5, 7+5+4)을 사용합니다.
DON'T
페이지별로 그리드 컬럼 수를 변경하지 않습니다 (12-col, 24-col 등 금지).
Gutter / Page Margin 토큰 값을 페이지별로 임의 변경하지 않습니다.
고정 px 폭(width:300px 등)으로 카드 폭을 지정하지 않습니다 — 반드시 span으로 표현합니다.
한 행에 span 합이 16을 초과하거나 미달하는 배치를 만들지 않습니다.
컨테이너에 max-width를 적용해 좌우 여백을 만들지 않습니다 — 페이지는 fluid 유지.
정의된 6개 breakpoint 외의 새로운 단점을 페이지별로 추가하지 않습니다.

Button

Refinery 의 모든 페이지에서 일관되게 사용되는 범용 버튼 시스템입니다. Primary 는 라이트·다크 모드 모두 Refined Blue(#76A6D7)를 사용하며, Primary 외 어떤 변형도 Refined Blue 를 사용하지 않습니다. 모든 버튼 라벨은 Pretendard / Roboto 폰트만 사용하며, Mono 폰트는 절대 사용하지 않습니다.

Widget

Refinery 의 모든 페이지에서 일관되게 사용되는 범용 위젯 시스템입니다. 위젯은 1depth(페이지에 직접 올라가는 카드)와 2depth(위젯 내부 중첩 박스) 두 단계로만 구성되며, 3depth 이상의 중첩은 금지됩니다. 라이트/다크 모드에서 동일한 시각적 계층(elevation)을 유지하도록 설계되었습니다.
Anatomy & Hierarchy

위젯은 페이지 배경 위에 올라가는 1depth 카드와, 그 안에 중첩될 수 있는 2depth 박스로 구성됩니다. 라이트 모드에서는 페이지가 옅은 회색, 1depth가 흰색, 2depth가 다시 옅은 회색으로 표면 톤이 순환합니다. 다크 모드에서는 페이지가 가장 어두운 톤, 1depth가 한 단계 밝은 카드 톤, 2depth가 다시 한 단계 더 밝은 톤으로 계층이 올라갑니다.

Rules · Do & Don't

Widget 시스템의 핵심 규칙입니다. 새 페이지·기능에 위젯을 추가할 때 예외 없이 적용됩니다.

DO
모든 컨텐츠는 1depth 위젯(.rfn-widget) 안에 담아 페이지 배경 위에 올립니다.
위젯 내부에서 정보 그룹핑이 필요할 때만 2depth 박스(.rfn-box)를 사용합니다.
라이트는 흰 카드, 다크는 #191D22 카드 톤을 그대로 유지합니다.
1depth radius 12px, 2depth radius 8px로 위계 차이를 시각화합니다.
1depth padding은 head/body 모두 14/16px, 2depth padding은 10/12px로 통일합니다.
위젯 header는 Title + Sub + 우측 Actions 구조로 통일합니다.
Action 아이콘 순서: 확대 → 다운로드 → 더보기(⋯).
DON'T
3depth 이상으로 박스를 중첩하지 않습니다 — 정보가 더 필요하면 별도 1depth 위젯으로 분리.
2depth 박스에 shadow를 추가하지 않습니다 (1depth만 shadow 보유).
위젯 background를 페이지 토큰 외 임의 색상(브랜드 컬러 fill 등)으로 변경하지 않습니다.
위젯 radius 12 / 2depth radius 8 외 임의 값을 사용하지 않습니다.
위젯 padding을 페이지별로 변경하지 않습니다 (밀도 조정은 density 토큰으로 일괄 처리).
위젯 header divider를 제거하거나 색상을 변경하지 않습니다.
1depth 위젯을 다른 1depth 위젯 안에 중첩하지 않습니다 — 그리드 span으로 나란히 배치합니다.

수치 · 단위 · 진행도 등 정량 데이터는 우측 정렬, 텍스트 · 이름 · ID는 좌측 정렬합니다.
수치 셀에는 항상 .t-num (Roboto + tabular-nums) 또는 Mono 폰트를 사용해 자릿수 정렬을 맞춥니다.

drill-down 가능한 행은 우측에 chevron 셀을 두고 row hover 시 chevron 컬러를 활성화합니다.
DON'T
테이블을 Widget 없이 페이지에 직접 올리지 않습니다.
Header(TH) 텍스트에 일반 본문 톤(소문자 · ink-800)을 사용하지 않습니다.
TH/TD padding을 8/12 · 10/12 외 임의 값으로 변경하지 않습니다.

선택 행(.is-selected) 배경에 Refined Blue 외 색을 사용하지 않습니다.
한 행에 5개 이상의 sub-component(badge · progress · sparkline 등)를 동시에 넣어 정보 과부하를 만들지 않습니다.
Row hover와 selected 배경을 동일 톤으로 만들지 않습니다 — 위계가 사라집니다.

Popover

트리거(버튼·아이콘)에 의해 호출되는 부유(floating) 패널 컴포넌트입니다. 컨테이너는 동일하나 내부 컨텐츠 패턴에 따라 두 가지 변형을 사용합니다 — Menu(액션 리스트)와 Select(옵션 선택). Search variant는 Search/Input 컴포넌트에서 별도로 다룹니다.

Rules · Do & Don't

Popover 시스템의 핵심 규칙입니다. 새 페이지·기능에 Popover 를 추가할 때 예외 없이 적용됩니다.

DO
액션 리스트는 Menu variant, 옵션 선택은 Select variant를 사용해 의미를 분리합니다.
한 페이지에 동시에 노출되는 Popover는 최대 1개로 제한합니다.
되돌릴 수 없는 파괴적 액션(계정 삭제·팀 영구 제거 등)에만 Danger 모디파이어 + Separator를 사용합니다. 로그아웃처럼 되돌릴 수 있는 액션은 일반 항목과 동일한 위계로 둡니다.
Select Option의 활성 상태에는 brand-50 + brand-700(예외적 허용)을 사용합니다.
Popover 항목 라벨은 한글이면 Pretendard, 영문이면 Roboto 폰트를 사용합니다.
외부 클릭 / ESC / 항목 선택 시 자동으로 닫히도록 구현합니다.
Popover 가 화면 가장자리에 가까우면 자동으로 반대 방향으로 flip 합니다.
DON'T
Popover 안에 긴 폼·입력·복잡한 컨텐츠를 넣지 않습니다 — Dialog 또는 Side Panel을 사용합니다.
Menu 항목에 selected(.on) 상태를 사용하지 않습니다 — 액션은 실행 후 닫힘이 정상.
Popover 라벨에 Mono 폰트를 사용하지 않습니다. (Mono는 count 배지 · shortcut 전용)
Select Option의 활성색을 brand-50 외 임의 색(녹색·노랑 등)으로 변경하지 않습니다.
10개 이상의 항목을 한 Popover에 넣지 않습니다 — 그룹으로 분리하거나 Select 컴포넌트(input)를 사용합니다.
Popover 너비를 트리거 너비에 강제 맞추지 않습니다 (min-width 200, 자유 확장).
한 번에 여러 Popover를 동시에 열어두지 않습니다.

Modal

Refinery 의 모든 페이지에서 사용되는 부유 다이얼로그(Dialog) 시스템입니다. 모달은 사용자의 주의를 단일 작업에 집중시킬 때만 사용하며, 단순 안내·알림은 Toast/Inline alert, 보조 옵션은 Popover 를 우선합니다. 모든 모달은 동일한 래퍼 .rfn-modal 위에서 정의되며, 4단 사이즈 토큰(sm 360 / md 480 / lg 640 / xl 800)과 4가지 의도(Default · Confirm · Destructive · Detail)만 사용합니다.
Anatomy

모달은 최대 5개의 구성 요소를 가집니다 — Overlay · Container · Head · Body · Foot. Container 안은 항상 Head → Body → Foot 세로 흐름을 유지하며, Body 만 스크롤하고 Head/Foot 은 고정됩니다.

Rules · Do & Don't

Modal 시스템의 핵심 규칙입니다. 새 페이지·기능에 Modal 을 추가할 때 예외 없이 적용됩니다.

DO
모달은 사용자의 주의를 단일 작업에 집중시켜야 할 때만 사용합니다.
너비는 4단 토큰(sm 360 · md 480 · lg 640 · xl 800) 안에서만 사용합니다.
Foot 의 Primary 버튼은 항상 우측, Cancel/Tertiary 는 좌측에 배치합니다.
되돌릴 수 없는 파괴적 액션에만 .rfn-modal-head-icon--danger 와 .rfn-btn--danger 를 함께 사용합니다. 로그아웃·취소처럼 되돌릴 수 있는 액션은 일반 Confirm.
Close X 버튼과 aria-label="닫기" 는 모든 모달에 필수입니다.
모달 오픈 시 첫 입력 필드(또는 Primary 버튼)에 자동 포커스합니다. Destructive 는 Cancel 에 포커스.
Body 만 스크롤 가능하며 Head/Foot 은 항상 고정 노출합니다.
Foot 은 상단 1px 보더만으로 Body 와 분리합니다 (배경 톤 부여 금지).
Confirm·Success 등 짧은 모달에서 Body 를 생략하면 Head 의 하단 보더만 분리선으로 유지합니다 (Foot 의 상단 보더는 자동 제거). 분리선 두께를 인위적으로 조절하지 않습니다.
Body 가 1~2문장의 짧은 부연 텍스트일 때는 padding-top:12px 로 상단 여백을 한 단계 좁혀 Head 와의 의미 연결을 유지합니다 (기본 18px 보다 가볍게).
완료 알림처럼 액션이 필요 없는 단순 안내는 모달 대신 Toast 를 우선 사용합니다.
DON'T
모달 위에 또 다른 모달을 띄우지 않습니다 (스택). 필요하면 단일 모달의 step 으로 분리합니다.
4단 토큰 외 임의의 너비(예: 520px, 720px)를 사용하지 않습니다.
Primary 와 Danger 버튼을 같은 Foot 에 동시에 배치하지 않습니다.
Foot 에 회색 등 별도 배경 톤을 적용하지 않습니다 — 시선이 액션 영역으로 과도하게 이동해 본문 가독성이 떨어집니다.
Destructive Confirm 에서 ESC · click-outside 닫기를 허용하지 않습니다.
Overlay 에 backdrop-filter:blur 를 적용하지 않습니다 (성능 + 어지러움).
모달 안의 콘텐츠가 너무 길어 Foot 액션이 화면 밖으로 밀려나지 않도록 합니다 (max-height 강제).
XL 사이즈(800px)에 의존해 모달을 미니 페이지처럼 사용하지 않습니다. 그 정도 작업은 전용 페이지로 분리합니다.
탭 5개 이상, Stepper 4단계 이상을 모달 안에 넣지 않습니다.

Rules · Do & Don't

Tab 시스템의 핵심 규칙입니다. 새 페이지·기능에 Tab 을 추가할 때 예외 없이 적용됩니다.

DO
페이지·모달 레벨에는 1depth (.rfn-tabs, 40h, brand active) 를 사용합니다.
위젯 내부 view 전환에는 2depth (.rfn-tabs--depth-2, 32h, ink active) 를 사용합니다.
한 strip 안의 Tab 은 모두 동일한 위계(아이콘 유무·count 유무 일관성)를 유지합니다.
Tab 의 라벨은 한글이면 Pretendard, 영문이면 Roboto. Mono 폰트는 사용하지 않습니다(count 배지의 숫자만 Mono).
3~5 개 옵션엔 Full-width(.rfn-tabs--fill) 도 활용 가능합니다.
Active Tab 의 콘텐츠 영역은 Tab strip 바로 아래에 인접 배치합니다 (좌우 align 일치).
Tab 클릭 시 즉시 콘텐츠가 전환되며 (페이지 리로드 없음), URL 해시·라우터 동기화를 권장합니다.
DON'T
두 depth 이상 중첩(3depth 이상 Tab 안에 Tab) 을 만들지 않습니다 — 4단계 분기는 별도 페이지로 분리합니다.
1depth 와 2depth 를 같은 영역에 인접 배치하지 않습니다 — 위계가 시각적으로 충돌합니다.
2depth Tab 에 brand 컬러를 강제로 적용하지 않습니다 — ink 톤 유지가 위젯 내부 가독성을 보장합니다.
Tab 개수가 6개 이상이면 사용하지 않습니다 — Dropdown / Select / 별도 페이지를 권장합니다.
Tab 라벨에 모든 대문자(UPPERCASE) 자동 변환을 적용하지 않습니다.
Tab 의 active 인디케이터를 underline 외 다른 패턴(배경 fill · 좌측 indicator bar 등)으로 변경하지 않습니다 — Rail/Side 의 active 패턴과 혼동됩니다.
Segmented Control(.rfn-seg) 과 Tab 을 혼용하지 않습니다 — segmented 는 "옵션 중 단일 선택"(필터·정렬), Tab 은 "콘텐츠 영역 전환".

Toast

사용자 흐름을 차단하지 않고 짧게 노출되는 알림입니다. 페이지 우상단에 떠올라 일정 시간 후 자동 dismiss 되며, 액션이 필요 없는 단순 안내(저장 완료·복사·동기화 등)에 모달 대신 우선 사용합니다. 4가지 의도(brand/good/warn/danger)로 분류되며 의도 아이콘 + 텍스트 + 자동 dismiss 진행 바의 한 가지 패턴을 일관되게 따릅니다. Toast 안의 액션은 최대 1개로 제한합니다 — 복잡한 결정은 Modal 이 담당합니다.

Rules · Do & Don't

Toast 시스템의 핵심 규칙입니다. 새 페이지·기능에 Toast 를 추가할 때 예외 없이 적용됩니다.

DO
사용자의 흐름을 차단하지 않고 노출 가능한 단순 안내(저장·복사·동기화 완료 등)는 Modal 대신 Toast 를 우선 사용합니다.
의도는 4단(brand · good · warn · danger) 안에서만 선택하고, 같은 의도에는 같은 아이콘을 일관되게 사용합니다.
Toast 안의 액션은 최대 1개로 제한합니다 (되돌리기 · 다시 시도 · 자세히 보기 등).
액션이 있는 Toast 는 duration 을 Long(8s) 으로 늘려 사용자에게 클릭 시간을 확보합니다.
치명적 오류 · 사용자 확인이 반드시 필요한 알림은 Persistent(수동 dismiss only) 로 둡니다.
Close X 버튼은 모든 Toast 에 필수이며, aria-label="닫기" 를 포함합니다.
마우스가 stack 위에 있을 때 모든 Toast 의 자동 dismiss 진행이 일시정지됩니다.
한 앱에서 Toast 위치는 한 곳으로 통일합니다 (기본 top-right).
DON'T

Tooltip

트리거 요소(아이콘 버튼·잘린 텍스트·차트 데이터 포인트 등)에 호버·포커스 시 짧게 노출되는 보조 라벨입니다. 인터랙티브하지 않으며 (클릭/터치 불가, pointer-events:none) 페이지 위 표면 톤과 명확히 구분되도록 inverted 톤(라이트 모드 → 다크 bg, 다크 모드 → 라이트 bg)을 사용합니다. 한 줄 라벨이 기본이며, 멀티라인 설명·단축키 표시·제목+설명 조합을 모디파이어로 지원합니다. Popover·Modal 과 달리 사용자 입력을 받지 않습니다 — 액션이 필요하면 Popover 를 사용합니다.

Rules · Do & Don't

Tooltip 시스템의 핵심 규칙입니다. 새 페이지·기능에 Tooltip 을 추가할 때 예외 없이 적용됩니다.

DO
아이콘 단독 버튼에는 항상 Tooltip 으로 텍스트 라벨을 제공합니다 (접근성 + 학습성).
title/aria-label 을 함께 제공해 키보드/스크린리더 환경에서도 동일한 정보가 전달되도록 합니다.
키보드 단축키가 있는 액션은 .rfn-tooltip-kbd 로 함께 표시합니다.
잘린 텍스트(text-overflow:ellipsis)에는 full content 를 Tooltip 으로 노출합니다.
차트 데이터 포인트·테이블 셀 등 잦은 hover 영역엔 delay = Fast(100ms), 일반 버튼은 Default(500ms), 잘린 텍스트는 Slow(800ms).
화면 모서리에 가까우면 반대 방향으로 자동 flip 합니다.
ESC 키로 즉시 dismiss 가능하게 구현합니다.
DON'T
Tooltip 안에 인터랙티브 요소(버튼·링크·입력)를 두지 않습니다 — 액션이 필요하면 Popover 를 사용합니다.
이미 텍스트로 라벨이 노출된 요소(텍스트 버튼·아이콘+라벨 조합)에 중복 Tooltip 을 달지 않습니다.
3 줄 이상의 긴 설명을 Tooltip 에 넣지 않습니다 — Popover 나 도움말 페이지로 옮깁니다.
Tooltip 으로 중요 정보·에러 메시지를 노출하지 않습니다 (사라지면 다시 확인하기 어려움) — Inline Alert / Toast 사용.
같은 컨텍스트에서 inverted bg 외 다른 톤(흰 카드 스타일·brand 컬러 등)으로 변경하지 않습니다.
delay 토큰(100 / 500 / 800ms · focus-only) 외 임의 값을 사용하지 않습니다.
터치 디바이스에서 hover-only Tooltip 에만 의존하지 않습니다 — 터치엔 long-press 또는 명시적 인디케이터 동반.

Rules · Do & Don't

Carousel 시스템의 핵심 규칙입니다. 새 페이지·기능에 Carousel 을 추가할 때 예외 없이 적용됩니다.

DO
Layout 은 4단(single · multi-2 · multi-3 · multi-4) 안에서만 선택합니다.
Multi 의 기본은 multi-3 입니다 — 카드 그룹 표시의 가장 일반적인 형태.
슬라이드 수 2~7개는 dots, 8개 이상은 counter, 진행감 강조가 필요할 때는 progress 인디케이터를 사용합니다.
가장자리 슬라이드 도달 시 해당 방향 Arrow 는 자동 disabled 합니다.
키보드 ← / → 키 · Home / End · Tab 포커스 이동을 모두 지원합니다.
Auto-play 가 활성일 때 hover · focus 시 즉시 일시정지합니다.
prefers-reduced-motion: reduce 환경에서는 auto-play 를 비활성합니다.
슬라이드 콘텐츠는 동일한 시각 위계를 유지합니다 — 한 슬라이드만 강조하지 않습니다.
DON'T
페이지 주요 네비게이션(Tab · Side Nav 등)에 Carousel 을 사용하지 않습니다 — 사용자가 콘텐츠를 못 볼 위험.
사용자 결정·입력이 중요한 콘텐츠(폼 · 설정 · 카드 그룹)에 auto-play 를 적용하지 않습니다.
슬라이드를 10개 이상 한 Carousel 에 담지 않습니다 — Pagination 이나 Filter 로 분기 권장.
한 페이지에 2개 이상의 auto-play Carousel 을 동시에 두지 않습니다 — 사용자 주의 분산.
인디케이터 없이(dots · counter · progress 중 무엇도 없이) Arrow 만 사용하지 않습니다 — 현재 위치 정보가 사라집니다.
슬라이드 너비를 정의된 모디파이어 외 임의 값으로 변경하지 않습니다.
Arrow 디자인에 강한 강조(brand fill · shadow 과장 등) 를 적용하지 않습니다 — 슬라이드 콘텐츠가 우선.

Spacing · Radius · Shadow

Refinery 의 모든 페이지가 공유하는 간격(Spacing) · 모서리 반경(Radius) · 그림자(Shadow) 스케일입니다. 컴포넌트의 padding·gap·radius·elevation 은 아래 정해진 스케일 값과 그림자 토큰(--shadow-sm / --shadow / --shadow-card)만 사용하며, 임의의 값을 새로 만들지 않습니다. 모든 값은 라이트·다크 모드에서 동일하게 적용됩니다.

Badge · Tag · Chip

작은 라벨류 요소들의 위계입니다. Badge(.rfn-badge)는 카운트·상태·식별자 라벨, Tag(.rfn-tcell-tag)는 테이블 셀 안의 인라인 분류, Chip(.chip)은 필터·날짜 등 클릭 가능한 인터랙티브 토큰이자 카테고리·메타를 표시하는 정적 라벨(--static / --quiet)로도 쓰입니다. Pill(.pill)은 네비게이션 항목의 NEW·카운트 표식입니다. 의미가 겹치는 새 요소를 만들지 않고 이 4종 안에서 선택합니다.
